        // 错误处理逻辑

# Webpack 启动流程

## Webpack 启动流程详解

### 1. 命令执行链

```bash
cd webapp
make run
```

实际执行的是：
```bash
npm run run
```

而 `npm run run` 执行的是：
```bash
node scripts/run.mjs
```

---

## 2. `scripts/run.mjs` 的作用

这个脚本使用了 `concurrently` 库来**并行运行多个 npm 命令**：

```javascript
const commands = [
    {command: 'npm:run --workspace=channels', name: 'webapp', prefixColor: 'cyan'},
];

commands.push(...getPlatformCommands('run'));
```

### 2.1 主要命令
- `npm:run --workspace=channels`：在 `channels` 工作区执行 `npm run run`
- `getPlatformCommands('run')`：在所有 `platform/` 开头的包中执行 `npm run run`

### 2.2 工作区（Workspaces）
根据 `package.json`，这个项目使用了 npm workspaces：
```json
"workspaces": [
    "channels",
    "platform/client", 
    "platform/components",
    "platform/eslint-plugin",
    "platform/mattermost-redux",
    "platform/types"
]
```

---

## 3. 回到 `channels` 包

当执行 `npm:run --workspace=channels` 时，实际是在 `channels` 目录下执行：
```bash
npm run run
```

而 `channels/package.json` 中定义：
```json
"run": "webpack --progress --watch"
```

---

## 4. Webpack 启动过程

### 4.1 直接启动
```bash
webpack --progress --watch
```

### 4.2 Webpack CLI
- `webpack` 命令来自 `webpack-cli` 包
- 它会读取 `webpack.config.js` 配置文件
- 根据配置启动构建过程

### 4.3 构建模式
- `--progress`：显示构建进度条
- `--watch`：监听文件变化，自动重新构建

---

## 5. 完整的启动流程

```
make run
    ↓
npm run run (webapp/package.json)
    ↓
node scripts/run.mjs
    ↓
concurrently([
    'npm:run --workspace=channels',
    ...platform commands
])
    ↓
npm run run (channels/package.json)
    ↓
webpack --progress --watch
    ↓
webpack-cli 读取 webpack.config.js
    ↓
开始构建和监听文件变化
```

---

## 6. 为什么这样设计？

### 6.1 多包并行构建
- 项目分为多个 npm 包（channels + platform/*）
- 需要同时构建所有包
- `concurrently` 让它们并行运行

### 6.2 工作区管理
- 使用 npm workspaces 管理多包项目
- 共享依赖，避免重复安装
- 统一的构建和开发流程

### 6.3 开发体验
- 一个命令启动所有相关服务
- 实时监听所有包的变化
- 统一的日志输出
