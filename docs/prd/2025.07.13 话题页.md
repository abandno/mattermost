## 功能1：话题首页

1. mattermost 聊天窗中的回复串、引用串，组成了帖子的内容。串的收条消息作为帖子的话题，后续消息作为评论，后续消息的引用，作为其在话题页中的评论的回复。
2. 首页展示该用户能看到的频道中的帖子。两个列表：1）最热，即回复数最多的；2）最新，即最新回复时间最新的。


查讨论串头消息
```sql
SELECT *
FROM (
    -- 子查询1：从 threads 关联中取 replycount < 1000 的前10条 posts
    (
        SELECT p.*, t.replycount, 'threads' as thread_type
        FROM posts p
        JOIN threads t ON p.id = t.postid
        WHERE p.deleteat = 0 AND t.replycount < 1000
        ORDER BY t.replycount DESC
        LIMIT 10
    )
    UNION ALL
    -- 子查询2：从 replythreads 关联中取 replycount < 1000 的前10条 posts
    (
        SELECT p.*, t.replycount, 'replythreads' as thread_type
        FROM posts p
        JOIN replythreads t ON p.id = t.postid
        WHERE t.replycount < 1000
        ORDER BY t.replycount DESC
        LIMIT 10
    )
) AS combined_results
ORDER BY replycount DESC
LIMIT 10;
```

	// 两种threads一起排序取top, 然后关联出posts

### 回复列表

*post的类型 + post的回复*


* post的类型:
1. thread
2. replythread

* post所在位置
- topic
- comment
- reply

* 要查的回复层级(评论or回复), 咱只有thread+topic会有lvl2的情况.

* 目前的情况枚举:
1. thread + topic + lvl1 : 评论列表. 讨论串里找. posts 表 rootId等于入参topicId的就是回复列表
2. thread + topic + lvl2 : 话题的直接回复列表, 相当于作为话题的补充描述、副标题. 引用串中找, 当前话题时间之后的引用串. postreply表中, ~~rid等于入参rid且创建时间在当前topic时间之后的~~(不对, 会将其他引用串的回复拿到. 改成和下面4通用的逻辑"postreply表pid等于topicId的及其后代回复")
3. replythread + topic : 引用串. 且暂定也分两层，引用串里找，直接引用的。postreply表pid等于当前topicId的.
4. replythread + comment : 因为暂定分两层, 所以评论位置的也要查回复。引用串里找，直接引用我的和间接引用我的，即所有后代。postreply表pid等于topicId的及其后代

* "postreply表pid等于topicId的及其后代回复", 太多怎么解决; 递归很多层可能没法查全; 按时间分页, 没法局部查, 拿到全部才知道怎么分页。
  * 往后“加载更多”的模式。
  * 方案1：
    * ~~sql里每次限定递归3次limit N，查到内存里，如果小于N/2，再来sql递归3次limit N；~~ sql递归6次limit N。
    * 达到了了N，该引用串消息提升出独立话题，当前评论区以连接方式，连接这个话题。作为话题，评论区两层结构的话，能消除一层递归。
  * **方案2**：
    * 或者，postreply表增加一个第二层的id（srid，rid的son，sub rid），下层节点都会带上rid和srid，如此，在保持评论-回复两层结构时，代码逻辑就变得很简单了。
    * 引用串就只能根能放到topic位置展示。否则又会绕到串中的回复列表需要纠结递归策略问题。

```sql
WITH RECURSIVE descendants AS (
    -- 初始查询：level = 1（直接子回复）
    SELECT *, 1 AS level 
    FROM postreply 
    WHERE 
--     pid = 'zcw4b6g9h7by7yx955c38o9sch' 
    pid = 'zcw4b6g9h7by7yx955c38o9sch' 
    AND deleteat = 0
    AND postid <> pid -- 必须排除自己，否则出现循环引用，递归会有很多重复行
    
    UNION ALL
    
    -- 递归查询：level + 1（子回复的子回复）
    SELECT pr.*, d.level + 1
    FROM postreply pr
    INNER JOIN descendants d ON pr.pid = d.postid
    WHERE pr.deleteat = 0
    AND d.level < 3  -- 限制递归深度不超过 3 层
)
-- 最终查询：按 updateat 降序排序，并限制 10 条
SELECT * FROM descendants
ORDER BY updateat DESC
LIMIT 10;
```




### postgres 递归查询示例

```sql
WITH RECURSIVE descendants AS (
    SELECT * FROM postreply WHERE pid = $1 AND deleteat = 0
    UNION ALL
    SELECT pr.* FROM postreply pr
    INNER JOIN descendants d ON pr.pid = d.postid
    WHERE pr.deleteat = 0
    AND updateat < 123456789
    ORDER BY updateat DESC
)
SELECT * FROM descendants;

SELECT p.* FROM posts p
JOIN (
    -- 上面递归查出来的所有 postid
    WITH RECURSIVE descendants AS (
        SELECT * FROM postreply WHERE pid = $1 AND deleteat = 0
        UNION ALL
        SELECT pr.* FROM postreply pr
        INNER JOIN descendants d ON pr.pid = d.postid
        WHERE pr.deleteat = 0
    )
    SELECT postid FROM descendants
) t ON p.id = t.postid
```
